# Как обновляется витрина

Новости и описание подготовленной сборки публикуются с рабочего компьютера сопровождающего при успешной отправке изменений основной ветки. Используется уже настроенная авторизация GitHub. Отдельных SSH-ключей и токенов для доступа к приватной репе в этой витрине нет.

Локальный скрипт экспортирует только выделенный публичный канал из отправленного коммита, проверяет его и обновляет страницы. Черновики, исходники приложения и локальные изменения рабочей копии не переносятся. Если содержимое не изменилось, новый коммит не создаётся. Для работы нужны включённый компьютер, интернет и доступ на push; при ошибке сопровождающий получает предупреждение и может повторить синхронизацию.

В этом репозитории хранится только уже опубликованный канал `public-channel`. Стандартный GitHub Actions runner проверяет генератор и обновляет ссылки при публикации/изменении Releases, вручную через Actions и примерно раз в 15 минут. Он читает только этот публичный репозиторий. GitHub может задерживать расписание и отключать его после длительной неактивности.

Исходники приложения здесь не собираются. Ни локальная синхронизация, ни публичный workflow не загружают EXE/ZIP и не создают релизы. Файлы Client публикуются отдельным решением владельца; Plus остаётся анонсом до запуска подписок. Ссылки на скачивание появляются только для фактически опубликованных файлов.

Отдельный сервер и платный API не нужны. Стандартные Actions в публичной репе бесплатны; артефакты и кеши Actions не создаются. [Условия GitHub Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions).
