# Как обновляется витрина

Публичные новости и сведения о подготовленной сборке хранятся в выделенной папке `public-channel` основной рабочей репы. Это отдельные тексты для пользователей, а не копия истории коммитов или исходников.

Workflow `Sync public showcase` запускается в этом публичном репозитории на стандартном Ubuntu runner примерно раз в 15 минут. Его можно запустить вручную через Actions. GitHub может задерживать расписание, а после длительной неактивности отключать его; тогда workflow нужно снова включить.

1. Из источника читается только папка публичного канала через sparse checkout.
2. Проверяются формат, разрешённые файлы и отсутствие явных приватных данных.
3. Генерируются главная страница, новости, описание текущей сборки и страницы справки.
4. Коммит создаётся только при изменениях. Перечень доступных загрузок берётся из фактически опубликованных Releases этой витрины.

Приложение здесь не собирается. Скрипт не загружает EXE/ZIP, не создаёт релизы и не копирует исходники клиента. Plus остаётся анонсом. Файлы сборок публикуются отдельным решением владельца.

Стандартные GitHub Actions в публичной репе бесплатны; отдельный сервер и платный API для этой синхронизации не нужны. Артефакты и кеши Actions не создаются.

Для чтения выделенного источника используется отдельный deploy key только на чтение. Он хранится в Actions Secrets, не в Git. Workflow не запускается из pull request и не исполняет скрипты из источника. Доступ на изменение workflow должен оставаться только у доверенных сопровождающих.

[Тарифы GitHub Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions).
